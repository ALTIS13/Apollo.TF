# Spotify saved albums

Source baseline: `890b35382c5280851df15317637c7e041c7b6253`. Scope: an authenticated metadata selection surface for portability. It does not write Spotify records into the TF library, stream Spotify, enable downloads, or perform automatic cross-provider matching. The earlier Spotify playlist profile and library actions remain unchanged.

## Contract

- `GET /api/spotify/albums` pages the connected account's [saved albums](https://developer.spotify.com/documentation/web-api/reference/get-users-saved-albums). Default and maximum page size are 10 to bound Spotify's nested track data under the existing response size cap. The provider drops documented taken-down entries with empty names without losing adjacent albums or the upstream page position.
- `GET /api/spotify/albums/:albumId/tracks` returns up to 50 [simplified tracks](https://developer.spotify.com/documentation/web-api/reference/get-an-albums-tracks) in source order, preserving disc/track numbers. The account's token and the existing `user-library-read` scope stay in the integrations service; no additional scope, identity provider, or migration. Album IDs are bounded alphanumeric and the client never follows upstream pagination URLs.
- Both routes require the live `tf.integrations` policy and sign the existing version-1 command envelope with the verified principal's account. Successful metadata receipts reject unexpected fields and require exact Spotify album/track links. The projections omit preview URLs, nested raw Spotify payloads and secrets. Both routes explicitly send `Cache-Control: no-store`, including for legacy TF sessions. Provider-not-connected and TF session errors stay distinct.
- Web adds Albums to the Spotify section of Collection, fetches only when that view is active, keeps list pagination on Back, and exposes exact Spotify links for each album and track. Selection/cache is scoped to verified TF account, installation and provider subject. A discarded view aborts its reads and late responses cannot alter the current auth state. No disk persistence or playback of provider audio was added. Attribution and provider policy still apply before public activation.
