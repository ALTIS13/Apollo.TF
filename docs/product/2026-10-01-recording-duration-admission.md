# Recording-aware duration admission

Status: local TF source complete and independently reviewed. Base `71f50cf`, branch `codex/tf-listener-experience`. This commit is the source checkpoint. No push, publication or deployment.

## Changed Behavior

- Removed the cross-song duration reference from candidate rejection. Artist, title, recording type and retained version/clean/remaster qualifiers now scope the comparison. Only recognized presentation suffixes and explicit YouTube uploader labels normalize; unrelated/unknown channels do not establish an artist identity.
- Exact search, free-text search and artist discovery obtain server-side catalog metadata once alongside selected audio providers, using the original query and the existing bounded Deezer result budget. There is no per-track lookup fan-out. Selected audio sources and the public v1 search DTO stay unchanged; metadata lookup is independent of audio source selection.
- Deezer catalog references do not depend on a playable preview URL. Version metadata is preserved, fields are validated, and preview audio remains rejected. No protected full audio is fetched from Deezer or Spotify.
- Matching catalog durations must agree within two seconds. A present conflicting catalog group remains unknown even if a long matching peer exists; only an absent usable catalog group allows agreeing peer fallback. Genuine short recordings and distinct live/remix/clean/remastered versions are not rejected using another recording's duration.
- Catalog/media queries share a five-minute, 256-entry LRU cache and at most 16 distinct pending requests; failures are not cached. Requests go only to the fixed HTTPS catalog endpoint with the existing eight-second timeout and at most 25 returned entries.
- Catalog failures use sanitized `catalog_reference_failure` logging, warn in aggregate search telemetry, and prevent successful result caching. No new public telemetry field or DTO was introduced. Catalog-backed search snapshots are capped at five minutes instead of the legacy hour. With the separate provider cache, metadata age can reach ten minutes; cache hits do not slide either expiry.
- Fixture runtime has no network catalog dependency. Existing preview URL/title filters, source rejection counts, ranking and auth/policy boundaries remain in force.

## Boundaries And Next Action

Catalog metadata is a comparison reference, not proof of complete audio, license, entitlement or decode integrity. Missing/ambiguous metadata, aliases or unsupported title presentation can remain unknown. Existing heuristic thresholds are unchanged: known reference at least 90 seconds, candidate at most 90 seconds and ratio at most 0.55. Unknown durations and excerpts longer than 90 seconds are not newly guaranteed to be rejected. Source acceptance is not playback acceptance.

Platform remains identity/policy authority. No API migration, worker, native release packet, HomeNode, Caddy, Coolify, UFW, Remnawave, browser UI or Android state was changed. The primary catalog proof is from this Windows PC, not the server runtime. Live OAuth/provider/audio/physical-device acceptance remains unestablished by this slice.

Next source stage: bind a trusted TF-issued recording reference to the selected source and actual playback/download admission, with server-owned version/expiry, existing account/installation/capability gates and a compatible internal contract. The browser's `expectedDurationSeconds` remains only a hint; this change does not promote it to authority or persist a catalog reference in the existing public v1 DTO. Keep existing stream/worker duration probes rather than implementing another preview checker. Source/reference expiry must be explicit at that boundary, not inferred from a cache hit.

Read-only next-boundary handoff found no reusable signed recording-reference/store in the inspected routes, search contract/gateway, worker processor or media-link limiter. The limiter is resource control, not a recording authority. Reuse [the signed private gateway](../../artifacts/api-server/src/lib/tf-search-client.ts), [route admission and enqueue boundaries](../../artifacts/api-server/src/routes/tracks.ts), and [existing source/final-file probes](../../artifacts/tf-download-worker/src/processor.ts). Imported queue/store/auth implementations still need targeted inspection before claiming persistent or worker-authority guarantees. Known references must not be weakened by omitted/small client hints; universally rejecting all unknown legacy IDs is a separate behavioral decision, not part of this slice.
