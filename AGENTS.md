# Repository working rules

Follow the current explicit user/coordinator assignment. Its approved scope
survives pauses and compaction; a generic "continue" does not expand that scope.
Historical documents are reference, not permission to restart accepted stages,
delegate, install tools, change another project, alter runtime or deploy.

For unified Apollo work, use the assigned brief and owner journal named by:
C:/Users/maksi/Desktop/Apollo.Platform/docs/operations/2026-09-05-unified-execution.md.
If unavailable, ask for the current handoff instead of guessing the next stage
from an old roadmap. Read only task-relevant reference sections.

Ownership: Supabase owns identity/source sessions; Platform owns entitlements,
policy, audit and admission; GAP owns network control/runtime; TF owns TF
runtime/BFF/player behavior. Module codes are extensible, not a closed enum.
Unknown or unsupported modules/capabilities never grant access: fail closed and
preserve established identity, contract and capability compatibility boundaries.

Use the assigned checkout/worktree. Check HEAD and dirty state; preserve other
owners' edits. Keep changes small and validate the affected behavior required by
the brief. Do not repeat accepted unchanged suites or activate runtime merely
because source checks passed. Report actual evidence, limitations and file scope.

Do not expose secrets or inspect private operational files without active-task
authorization. Existing approval is not erased by a pause; ask again only for a
new destructive action, changed scope/risk or missing authority. Do not infer
such approval from historical deploy examples or standing tool permissions.

Discover tools and skills from the current session. Old catalogs are not proof
of availability. Do not create parallel workers without current authorization.

TF references: use pnpm and the existing OpenAPI/code-generation flow. Preserve
frozen contracts and compatibility capability keys. CODEX_REFERENCE.md retains
architecture/mobile decisions only; old TF/Web plans are reference-only. The
assigned owner/sub-slice journal, not the oldest journal header, binds resumption.
